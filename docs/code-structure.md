# Code structure

Where code lives and which part may import which. How the parts behave at run time is in [`architecture.md`](./architecture.md).

The repository is a pnpm workspace (`pnpm-workspace.yaml`) with two apps and two packages, built with Turborepo (`turbo.json`).

| Package | Folder | Role |
|---|---|---|
| `@cfx-mail/worker` | `apps/worker` | The Cloudflare Worker: API, inbound mail, cron, IMAP, the `UserHub` Durable Object. |
| `@cfx-mail/web` | `apps/web` | The React single-page app, served by the Worker as static assets. |
| `@cfx-mail/db` | `packages/db` | Database schema, column enums and migrations. |
| `@cfx-mail/shared` | `packages/shared` | Request schemas, response types, event types, permission and flag bits. Used by both apps. |
| | `scripts` | Deploy, backup and restore (Node, run from a developer's machine). |

## `apps/worker`

| Path | Responsibility |
|---|---|
| `src/index.ts` | The Worker entry. Exports `fetch`, `email`, `connect`, `scheduled` and `UserHub`. Holds the app-shell security headers. |
| `src/api/` | HTTP transport. `index.ts` composes every route group in one Hono chain and turns errors into JSON. One file per route group (`messages.ts`, `threads.ts`, `mailboxes.ts`, `admin.ts`, `svc.ts` and so on). `stream.ts` opens the SSE stream. `pagination.ts`, `serialize.ts` and `util.ts` are helpers for the routes. `message-body.ts` renders stored message bodies for the reader, for the single-body and the thread-bodies route. `validate.ts` is the `zValidator` every route uses; it answers a failed validation with `{ error: "<sentence>" }`. |
| `src/mail/` | Mail logic, independent of any transport. Inbound: `receive.ts` (pipeline), `ingest.ts` (storage), `threads.ts` (threading), `spam.ts`, `dnsbl.ts`, `dns.ts`, `rules.ts`, `rule-sends.ts`, `blocklist.ts`, `calendar.ts`, `otp.ts` (one-time codes). Outbound: `send.ts`, `quote.ts`, `notify.ts`, `unsubscribe.ts`. Reading: `sanitize.ts`, `hidden-style.ts`, `img-proxy.ts`, `trackers.ts`. Storage: `blob-keys.ts` (every R2 key layout), `blobs.ts`, `orphan-blobs.ts` (the hourly sweep of unreferenced uploads and avatars), `attachment-keys.ts`, `mime.ts`. Push: `push.ts`, `webpush.ts`. PGP: `pgp.ts`, `wkd.ts`. |
| `src/imap/` | The IMAP server (not in use). `index.ts` takes the socket, `session.ts` is the protocol state machine, `protocol.ts` the wire format, `store.ts` maps mailboxes to IMAP folders and owns the UID tables, `fetch.ts`, `search.ts` and `mime-tree.ts` serve FETCH and SEARCH, `hub-listener.ts` wakes `IDLE`. |
| `src/lib/` | Small pure helpers with no local imports: `encoding.ts`, `html-strip.ts`, `sql.ts` (D1's 100-parameter chunking), `unread.ts` (the unread recount shared by `api/` and `imap/`). |
| `src/shims/` | Small stand-ins for two dependencies, wired through `alias` in `wrangler.jsonc`. |
| `src/auth.ts`, `auth-ctx.ts`, `middleware.ts` | Better Auth setup, per-request auth instance, and the `sessionMiddleware`, `requireUser`, `requireAdmin` guards. |
| `src/permissions.ts`, `mailbox-access.ts` | Mailbox access checks, and who may create which mailbox type on a domain. |
| `src/config.ts` | `system_config` access and the lazily created secrets. |
| `src/cron.ts` | The fourteen scheduled steps. |
| `src/hub.ts` | The `UserHub` Durable Object and `broadcastToUsers`. |
| `src/app-passwords.ts` | IMAP app-password login. |
| `src/mailbox-purge.ts` | Marks a mailbox for the staged purge. |
| `src/rate-limit.ts`, `ssrf.ts`, `errors.ts`, `env.ts`, `db.ts` | Rate limiting, the SSRF guard, `AppError`, binding types, the per-request database handle. |
| `test/` | Vitest in the Workers runtime (`vitest.config.ts`). `test/api/` holds one file per route group; `test/support/` holds the harness ([`test/support/README.md`](../apps/worker/test/support/README.md)). |
| `wrangler.jsonc` | Bindings and deployments ([`config-reference.md`](./config-reference.md)). |

## Dependency direction

These rules were checked by reading every import in `apps/worker/src`, `apps/web/src`, `packages/db/src` and `packages/shared/src` on 2026-10-09.

Between packages:

- `packages/db` imports no workspace package.
- `packages/shared` imports `packages/db` (`enums.ts` values, `schema.ts` types) and nothing else.
- `apps/worker` imports `packages/db` and `packages/shared`.
- `apps/web` imports `packages/shared`, and the Worker's route types once, type-only (`import type { AppType } from "@cfx-mail/worker/api"` in `src/lib/api.ts`). It imports no Worker code and no `@cfx-mail/db` directly.

Inside `apps/worker/src`:

| From | May import | Never imports |
|---|---|---|
| `index.ts` (entry) | anything | |
| `api/` | `mail/`, root modules, `lib/` | `imap/` |
| `imap/` | `mail/`, root modules, `lib/` | `api/` |
| `mail/` | root modules (`config.ts`, `env.ts`, `errors.ts`, `hub.ts`, `permissions.ts`, `ssrf.ts`), `lib/` | `api/`, `imap/` |
| root modules | `mail/`, other root modules, `lib/` | `api/`, `imap/` (only `index.ts` does) |
| `lib/`, `shims/` | nothing local | everything |

Two more rules come from `AGENTS.md`:

- `HTTPException` belongs to `api/` only (invariant 9).
- Only `imap/store.ts` writes `imap_folder` and `imap_uid` (invariant 12). This holds today.

### Findings

- Violation of invariant 9: `apps/worker/src/middleware.ts` is a root module and throws `HTTPException` in `requireUser` and `requireAdmin`. It is used only by `api/`, so the effect is contained, but the rule as written is broken.
- Root modules and `mail/` depend on each other at folder level. `auth.ts` imports `mail/notify.ts`, `config.ts` imports `mail/pgp.ts`, `app-passwords.ts` imports `mail/dnsbl.ts`, and `cron.ts` imports nine `mail/` modules, while `mail/` imports `config.ts`, `hub.ts`, `permissions.ts` and others. No rule forbids this and there is no file-level runtime cycle.
- One type-only cycle: `env.ts` imports the `Auth` type from `auth.ts`, which imports the `Env` type from `env.ts` (also through `config.ts` and `mail/notify.ts`). It has no runtime effect.
- `DELETE /api/mailboxes/:id` (`api/mailboxes.ts`) checks `ownerUserId` itself instead of going through `permissions.ts`. It is an owner-only rule, not a copy of the owner shortcut, so it does not break invariant 2.

### What is machine-enforced

`scripts/architecture.test.mjs` reads every import in the workspace and fails when one breaks a direction rule above, naming the file. It runs with `pnpm test`. `.oxlintrc.json` also refuses `hono/http-exception` outside `apps/worker/src/api/`.

Two older checks help as well:

- Biome's `useImportType` rule is an error, so an import used only for types must be written `import type`. It keeps the web app's import of the Worker type-only once it is written that way.
- `@cfx-mail/worker` exports `./api` with only a `types` condition (`apps/worker/package.json`). A value import of it from the web app would probably fail the Vite build. This is not tested.
